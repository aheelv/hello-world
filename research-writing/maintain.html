维护与持续更新

内容即数据：日常更新只改一个文件，构建与校验脚本负责拦截错误。

核验日期 资源 项证据分级 A–D不承诺发表结果

一、架构：与工作区既有站点一致

本项目沿用工作区 se-ai-harness-site 已验证的静态架构：纯 HTML/CSS/JS、零第三方运行时依赖、Node.js 内置模块完成构建与冒烟校验。新增的两点是内容数据化与内容校验门禁。

路径职责
src/data/site-data.js唯一内容数据源：资源库、译介、策略、合规清单、术语表、证据等级、变更记录、未收录项。页面只写叙述性正文。
src/assets/app.js把数据渲染进 data-render / data-related 挂载点；处理筛选、搜索与导航高亮。
src/assets/site.css / site-nav.css共享设计系统与导航条；含响应式、打印样式与可访问性焦点样式。
scripts/check-content.mjs内容门禁：校验必填字段、ID 唯一、URL 合法、等级/阶段枚举、策略与清单的引用编号真实存在。
scripts/build.mjs清理 dist → 校验 HTML 结构与所有内部引用 → 校验 data-render 挂载点与正文 Rnn/Tnn 锚点均可解析 → 复制 → 生成 dist/build-info.json。
scripts/verify.mjs临时端口启动 dist，逐页请求 200、内部链接可达、构建清单可解析。
scripts/generate_pages.py页面生成器（内容编写工具）。重跑会覆盖 src/*.html；已直接手改 HTML 正文时不要盲目重跑。

二、日常更新流程

  1. 新增/修订资源：编辑 src/data/site-data.js 的 resources 数组，填写全部必填字段，并同步更新 meta.verifiedAt 与 changelog。
  2. 若新增策略或合规条目，evidence 数组中的 Rnn 编号必须已存在于资源库，否则内容校验会失败。
  3. 运行 npm run check 做内容校验；运行 npm run build 做结构与内部链接校验。
  4. 运行 npm run verify 做部署前冒烟校验（逐页 HTTP 200、内部引用可达、构建清单一致）；全绿再发布 dist/。
  5. 纯静态产物，可部署到任意静态托管或直接用 scripts/serve.mjs 单端口服务。

命令一览：npm run dev（预览 src） · npm run check · npm run build · npm run preview · npm run verify · npm run deploy（check + build + verify）。无需 npm install。

三、资源新增规范

字段必填要求
id是形如 R54，全库唯一且只增不改；其他内容通过编号引用。
zh / en / org / url是中英文名称、发布机构、原始 https 链接；不使用短链或聚合站。
level / kind / stages是level ∈ A/B/C/D；stages 为阶段 id 数组；kind 用于资源库类型筛选。
audience / time / note / caution是适用对象或场景、时效/版本、中文译介、适用边界与误用风险。缺 caution 的条目不予收录。
status是ok / bot / redirect；描述本次核验的链接状态，不描述内容质量。
stars / starsAtGitHub 项必填通过 GitHub API 读取并注明读取日期；不得凭印象填写。
审慎原则：不收录无法核验的链接，不把搜索结果摘要当作原文，不补写原文没有的数字与结论。若某条政策未能从官方页面核实（例如本站对 ICMJE 二次发表条款的处理），应在正文中明确写「未能核验」而非推测。

四、核验方法（）

  • 链接可达性：对全部候选 URL 发起带浏览器 UA 的 HTTPS 请求，记录状态码与最终跳转地址。
  • 反爬站点：对返回 403 / 412 的官方站点（COPE、Science、PLOS、DOAJ、NIH、T&F、AOM、DORA、rOpenSci 文档站等），改用内容抓取获取正文后再判断；这部分资源在卡片中标注为「反爬拦截」，不声称其链接对所有人返回 200。
  • 中文法规：以发布机关官网（科技部、国家卫健委、中国科协、中科院学部、国家标准全文公开系统）原文为准，记录发文字号、成文日期与有效性。
  • GitHub 星数：通过 api.github.com/repos/{owner}/{repo} 读取 stargazers_count 与 pushed_at，标注读取日期；星数会变化，不写进结论性表述。
  • 剔除留痕：星数不足、链接 404、域名变更等未收录项记录在下表，避免「只报喜不报忧」。
  • 定期复查：运行 npm run check:links 可重新逐条请求全部资源 URL 并报告「可达 / 反爬拦截 / 失效 / 未验成」四类状态。该脚本只在本地运行、不自动改写数据；网络超时不计为失效，确认变更后再人工更新 meta.verifiedAt 与 changelog。
巡检结果如何解读：脚本把结果分为「可达 / 反爬拦截 / 失效（404、410）/ 未验成（网络或超时）」四类。「未验成」不等于链接失效，反爬拦截也不等于内容不可用；只有明确的 404/410 才需要在人工复核后更新或移除条目。巡检结果随网络环境波动，不自动改变已记录的核验状态。
