# 超星知识图谱格式：兼容范围、字段映射与示例文件

> 本文件是项目的**格式契约**。所有页面读写 `data/course-kg.json` 这一份统一数据；与超星平台的文件交换全部经过 `io/js/converter.js` 的转换接口。
> 依据：用户上传的 `01-知识图谱-运筹学-7章全部.xlsx`（旧版 15 列）与本工作空间已有的 `知识图谱导入-运筹学7章-标准格式.xlsx`（新版 16 列）的**模板原文第 1/2 行**，而非推测。

## 一、两套超星模板的事实差异

| 项 | 旧版 15 列（上传源文件） | 新版 16 列（导入模板） |
| --- | --- | --- |
| 工作表 | `Sheet3` | `Sheet3` |
| 第 1 行 | 使用说明（A1:K1 合并） | 使用说明（A1:J1 合并） |
| 第 2 行表头 | 节点类型\* + 一~七级节点名称\* + 前置/后置/关联 + 标签 + 知识点分类 + 节点说明 | 一~七级知识节点 + 前置/后置/关联知识节点 + 节点类型 + 节点描述 + 难易程度 + 重难点 + 专业素养 + 应用能力 |
| 层级列 | B–H（8 列中的 7 级） | A–G |
| 节点类型取值 | `分类` / `知识点` | `知识单元` / `知识点` |
| 关系列 | I / J / K | H / I / J |
| 关系分隔符 | 英文分号 `;` | 英文分号 `;` |
| 独有字段 | 标签、知识点分类 | 难易程度、重难点、专业素养、应用能力 |
| 说明字段 | 节点说明 | 节点描述 |
| 模板硬约束 | 名称 ≤256 字符；知识点后不可有子级；节点 ≤5000、关系 ≤2000、标签 ≤1000 | 同左（另：M–P 仅知识点填写，知识单元留空；难易程度仅 5 个枚举值） |

> **重要细节**：关系名本身可能含顿号，例如「基、基变量、非基变量的概念」「特殊情况分析（无可行解、无界解、多重最优解）」。**只能按英文分号 `;` 切分**，按顿号切会错误拆成 6 个不存在的节点。转换器已按此实现，并在 `tools/build_data.py` 中做了回归校验（当前 0 处未解析引用）。

## 二、字段映射（新版 16 列 ↔ 统一数据）

| 列 | 超星表头 | 统一数据字段 | 类型 | 兼容级别 | 说明 |
| --- | --- | --- | --- | --- | --- |
| A–G | 一~七级知识节点 | `nodes[].level` + `name` + `parentId` + `path` | string | ✅ 完全 | 每行只有一个层级列有值；`parentId` 由层级栈推导 |
| H | 前置知识节点 | `nodes[].pre[]` → `edges(relation=前置)` | string | ✅ 完全 | 语义方向：被引用节点 → 当前节点 |
| I | 后置知识节点 | `nodes[].post[]` → `edges(relation=后置)` | string | ✅ 完全 | 语义方向：当前节点 → 被引用节点 |
| J | 关联知识节点 | `nodes[].related[]` → `edges(relation=关联)` | string | ✅ 完全 | 无向 |
| K | 节点类型 | `nodes[].type` | 枚举 | ✅ 完全 | `知识单元` / `知识点` |
| L | 节点描述 | `nodes[].description` | string | ✅ 完全 | 仅纯文本 |
| M | 难易程度 | `nodes[].difficulty` | 枚举 | ✅ 完全 | 容易/偏易/适中/偏难/难 |
| N | 重难点 | `nodes[].keypoint` | string | ✅ 完全 | 可含 `重点;难点` |
| O | 专业素养 | `nodes[].literacy` | string | ✅ 完全 | — |
| P | 应用能力 | `nodes[].application` | string | ✅ 完全 | — |
| — | （无对应列） | `nodes[].tags[]` | string[] | ⚠️ 仅本项目 | 由旧版标签迁移而来，导出新版时不写回 |
| — | （无对应列） | `nodes[].category` | string | ⚠️ 仅本项目 | 事实性/概念性/程序性/元认知 |
| — | （无对应列） | `nodes[].sourceRow` | int | ⚠️ 仅本项目 | 溯源到源表行号 |

## 三、字段映射（旧版 15 列 → 新版 16 列 → 统一数据）

| 旧版列 | 旧版表头 | 新版对应列 | 转换规则 | 兼容级别 |
| --- | --- | --- | --- | --- |
| A | 节点类型\* | K 节点类型 | `分类` → `知识单元`；`知识点` 不变 | ✅ 无损 |
| B–H | 一~七级节点名称\* | A–G | 整体左移一列，层级语义不变 | ✅ 无损 |
| I | 前置节点 | H 前置知识节点 | 原样；挂空引用记入 `warnings` | ⚠️ 部分 |
| J | 后置节点 | I 后置知识节点 | 原样；同上 | ⚠️ 部分 |
| K | 关联节点 | J 关联知识节点 | 原样；同上 | ⚠️ 部分 |
| L | 标签 | N 重难点（部分） | 仅 `重点` / `难点` 写入 N；其余标签（考点、课程思政、应用导向、实操性…）保留在统一数据 `tags[]`，**新版 xlsx 无列可写** | ⚠️ 有损 |
| M | 知识点分类 | — | 新版无对应列；保留在 `nodes[].category` | ⚠️ 有损 |
| N | 节点说明 | L 节点描述 | 原样 | ✅ 无损 |
| — | （无） | M / O / P | 难易程度、专业素养、应用能力旧版无数据：导出时**留空并提示**，或按标签规则推导（本项目统一数据中已有推导结果） | ⚠️ 需补录 |

**新版 → 旧版** 的反向转换同样有损：M–P 四属性无列可写；`知识单元` 需回写为 `分类`；标签只能由 `keypoint` 还原出重点/难点。导出旧版时会在页面给出明确的有损字段清单，不会静默丢弃。

## 四、兼容范围声明（明确边界）

### ✅ 完全兼容（文件级无损往返）
1. 16 列新版 `.xlsx` / `.csv` 的**读取**：A–P 全部字段、第 1 行使用说明、第 2 行表头、`Sheet3` 工作表名。
2. 16 列新版 `.xlsx` 的**写出**：按模板原样生成第 1 行说明与第 2 行表头，数据自第 3 行起，每行仅填自身层级列；知识单元 M–P 留空。
3. 层级 1–7 级、节点类型、三类关系、四属性的 JSON 化与反 JSON 化。
4. 模板硬约束校验：名称 ≤256、节点 ≤5000、关系 ≤2000、标签 ≤1000、知识点不得有子级、任意两节点仅一种关系（新关系覆盖旧关系）、难易程度枚举合法。

### ⚠️ 部分兼容（通过 `io/js/converter.js` 转换接口完成，结果带警告清单）
1. 旧版 15 列 ↔ 新版 16 列 ↔ 统一 JSON 的双向转换（上表所列有损字段）。
2. 关系引用指向不存在节点：保留到 `unresolvedReferences` 并在导入结果中逐条列出，导出时剔除。
3. 标签体系与知识点分类：保留在统一数据扩展字段，但不写回 xlsx。
4. 关系方向的合并去重：源表存在"两侧各写一次"的重复声明，按模板"任意两节点只存在一种关系"合并，优先落在前置列。

### ❌ 不在兼容范围（需平台侧或另行处理）
1. **平台 API 级同步**：本系统是纯静态站点，不调用超星在线接口、不持有账号凭据，只做**文件级**导入导出；课程绑定、资源挂接、审核发布请在超星后台完成。
2. 图片、公式、LaTeX、附件、视频、题目/习题与知识点的挂载关系——模板明确"节点描述仅支持文本"。
3. 学习行为数据（掌握度、学习时长、推荐路径）、平台内图谱渲染样式与配色。
4. 7 级以上的层级、跨课程图谱合并、多工作表图谱。
5. 原模板的单元格样式（蓝色表头、合并、行高列宽）在**导入**时不需要；导出 xlsx 时保留表头文字与结构，样式由平台模板决定。
