# 数据转换接口说明（超星 ↩ 统一课程图谱）

> 实现文件：`io/js/converter.js`（浏览器端，UMD 风格挂载到 `window.KGConverter`），零依赖服务端；依赖本地 `assets/vendor/xlsx.full.min.js`（SheetJS 0.18.5）读写 xlsx。
> 在线试验：`io/index.html` → ③ 数据转换接口。

## 一、为什么要提供转换接口

超星知识图谱存在**两代模板**（旧版 15 列、新版 16 列），且平台在线接口不对外暴露。本系统因此明确把兼容边界划在**文件级**：

- 新版 16 列：可无损往返（读写同一份表头与使用说明）；
- 旧版 15 列 ↔ 新版 16 列 ↔ 统一 JSON：**有损**，必须通过转换接口完成，且必须输出「有损字段清单」；
- 平台在线能力（账号、课程绑定、资源挂接、审核发布）：不在范围，到超星后台完成。

## 二、公开 API

| 接口 | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `detectFormat(rows)` | 表格二维数组 | `'chaoxing16'` / `'chaoxing15'` / `'unknown'` | 扫描前 5 行表头关键字，不依赖文件扩展名 |
| `readWorkbook(arrayBuffer)` | xlsx 文件 ArrayBuffer | `{format, headerRow, sheet, header, rows, sheetNames}` | 优先取 `Sheet3`；自动定位表头行（通常是第 2 行） |
| `parseRows(rows, format)` | 数据行 + 格式 | `{nodes, edges, warnings, unresolvedReferences, stats}` | 逐列映射、层级栈推导父节点、关系去重、硬约束校验 |
| `toUnified(parsed, meta)` | parseRows 结果 | 与 `data/course-kg.json` 同构的对象 | 补 `meta / schema / statistics / chapters` |
| `toChaoxing16(unified)` | 统一数据 | `{sheet, note, header, rows, lostFields}` | `note` 为模板第 1 行原文，`header` 为 16 列表头原文 |
| `toChaoxing15(unified)` | 统一数据 | 同上 | 类型回写 `分类`；输出有损字段清单 |
| `exportWorkbook(unified, format, filename)` | 统一数据 + 目标格式 | 触发 `.xlsx` 下载 | 生成第 1 行说明（合并 A1:J1）、第 2 行表头、第 3 行起数据 |
| `validate(unified)` | 统一数据 | `{checks, warnings, passed}` | 11 项模板硬约束 |
| `loadUnified(jsonText)` | JSON 文本 | 统一数据 | 校验 `nodes / edges / meta` 结构 |

## 三、统一数据结构（`data/course-kg.json`）

```jsonc
{
  "meta": { "course": "运筹学", "nodeCount": 186, "edgeCount": 320,
            "chapterCount": 7, "singleSourceOfTruth": "data/course-kg.json", ... },
  "schema": { "node": [...], "edge": [...], "chapter": [...] },
  "statistics": { "byType": {}, "byLevel": {}, "byDifficulty": {}, "byRelation": {} },
  "headers": { "chaoxing15": [...], "chaoxing16": [...] },
  "chapters": [{ "id", "name", "nodeCount", "knowledgePointCount", "unitCount" }],
  "nodes": [{
    "id": "N001", "name": "绪论", "level": 1, "type": "知识单元",
    "parentId": null, "path": ["绪论"], "chapter": "绪论",
    "description": "", "difficulty": "", "keypoint": "", "literacy": "", "application": "",
    "tags": [], "category": "", "pre": [], "post": [], "related": [],
    "degree": 0, "sourceRow": 3
  }],
  "edges": [{ "id": "E0001", "source": "N005", "target": "N006",
              "relation": "前置", "undirected": false, "owner": "N006", "declaredAs": "前置" }],
  "unresolvedReferences": []
}
```

**关系方向约定**：`前置` 边为「被引用节点 → 当前节点」（先修方向）；`后置` 边为「当前节点 → 被引用节点」；`关联` 无向。`owner` / `declaredAs` 保留原始声明方向，用于反向导出时还原到正确的关系列。

**双格式数据文件**：`course-kg.json` 是规范真源；`course-kg.js` 是同一对象的 `window.COURSE_KG = {...}` 包装，供 `file://` 直接双击打开页面（浏览器禁止 `file://` 下的 `fetch`，故全部页面用 `<script>` 引入）。两者由 `tools/build_data.py` 一次性生成并校验相等。

## 四、转换规则（逐条可复现）

1. **切分**：关系列只按英文分号 `;`（兼容中文 `；`）切分；**不按顿号切**——节点名可含顿号，如「基、基变量、非基变量的概念」。标签列按 `;；、` 切分。
2. **层级**：每行仅取第一个非空层级列 → `level`；用层级栈推导 `parentId`；根节点的 `path[0]` 即 `chapter`。
3. **类型**：旧版 `分类` ⇄ 新版 `知识单元`；`知识点` 不变。
4. **关系唯一性**：按模板第 3/4 条「任意两节点只存在一种关系，新导入覆盖旧关系」，以无序节点对去重，保留最后声明的一条。
5. **空引用**：目标节点不存在时写入 `unresolvedReferences` 并在导入结果中列出，导出时剔除，不静默丢弃。
6. **自引用**：忽略并记警告。
7. **有损字段**：
   - 15 → 16：`tags` 仅 `重点/难点` 可写入 N 列；`category` 无列可写；M/O/P 留空并提示补录；
   - 16 → 15：`difficulty / literacy / application` 无列可写；`知识单元` 回写为 `分类`；`keypoint` 中的重点/难点还原为标签。
8. **硬约束**：节点名 ≤256、节点 ≤5000、关系 ≤2000、标签 ≤1000、层级 1–7、知识点无子级、知识单元 M–P 留空、难易程度 5 个枚举值、父节点可追溯、关系两端存在。
9. **导出复刻**：`note` 与 `header` 取自 `data/chaoxing/template-notes.js`（由 xlsx 第 1/2 行原文自动提取），不手写、不猜测。

## 五、调用示例

```js
// 浏览器：读取用户选择的超星 xlsx
const buf = await file.arrayBuffer();
const input = KGConverter.readWorkbook(buf);              // 自动识别 15/16 列
const parsed = KGConverter.parseRows(input.rows, input.format);
const unified = KGConverter.toUnified(parsed, { course: '运筹学' });
const report = KGConverter.validate(unified);             // 11 项硬约束
console.log(parsed.warnings, parsed.unresolvedReferences);
KGConverter.exportWorkbook(unified, 'chaoxing16', '运筹学导入.xlsx');

// 15 列 → 16 列
const t16 = KGConverter.toChaoxing16(unified);
console.log(t16.lostFields);                              // 明确列出有损字段
```

## 六、往返一致性验证

`tools/verify.py` 会执行以下检查并在 `docs/04_一致性校验记录.md` 输出结果；`tools/test_converter.js` 另行验证转换接口的 22 项功能并写入 `docs/05_转换接口测试记录.md`：

1. `course-kg.json` 与 `course-kg.js` 内容完全相等；
2. 16 列示例 CSV 的每一列与统一数据字段逐行一致（186 行 × 16 列）；
3. 15 列示例 CSV 的层级、类型、关系与源文件一致；
4. 所有页面引用的数据文件均为 `data/course-kg.js`（静态扫描 HTML）；
5. 所有页面引用的第三方库均为本地文件（无 `http://` / `https://` 运行时依赖）。
